## Completed in code

1. **Concurrent email workers:** payment, receipt, completed-brief, support and summary queues now claim work atomically with a five-minute lease. Overlapping request/webhook/recovery workers do not deliver the same row concurrently. An expired lease is recoverable. A summary retry cannot reset an active lease. This does not promise exactly-once delivery after an ambiguous provider timeout; Make-side deduplication is still needed for that guarantee.
2. **Explicit launch gate:** production accepts new PayPal orders only with `CHECKOUT_ENABLED=true`, approved delivery text, database, Live PayPal credentials/webhook/payee, Make URL and authentication key, admin email, HTTPS site URL and cron secret, with no test-recipient restriction. Missing configuration closes both UI and API. Existence checks do not establish that external credentials work. Existing payment reconciliation is left available.
3. **Environment ownership:** Vercel's environment takes priority over a local override; Preview stays Sandbox. The browser starts with checkout closed until server configuration arrives.
4. **Bit:** disabled by default. It requires `BIT_ENABLED=true` and a valid `BIT_WHATSAPP` target in Production. The personal number is no longer hardcoded in the client. The agent's dynamic instructions and payment tool reflect the options actually available. Failed order creation leads to support instead of an untracked transfer.
5. **Honest payment errors:** an uncertain result never claims the buyer was not charged or suggests immediate repayment. A closed checkout is reported as closed by the page tool.
6. **Support:** terms/accessibility pages link to the working form instead of a personal phone. Keyboard focus stays in the form; closing restores scrolling/focus, including after a checkout failure. Closing while a save is in flight no longer causes the response to access a removed global form.
7. **Deployment hygiene:** `/test`, `/docs`, `/scripts` and root internal Markdown entry points redirect away from the public site. The GitHub repository is public; these redirects do not make repository contents private.
8. **Repeatable local checks:** the browser runner uses the installed Playwright browser (or `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`), waits for server readiness, streams output and stops its server on exit. Browser dependency is pinned in `test/requirements.txt`.
9. **Concurrent summary limits:** reservation and cap checking now run in one database transaction, with an environment-scoped transaction lock acquired before the counting statement. Eight simultaneous requests previously bypassed the two-message cap; the regression now permits only two. Per-order, per-address and site-wide caps, duplicate requests, failed-delivery reservations, expiry and rollback are covered. A malformed configured daily cap fails closed to one. No schema migration is needed.
