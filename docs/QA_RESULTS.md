## מה נבדק ואיפה
- **אינטגרציה (15 בדיקות, `npm test`):** קוד השרת האמיתי מול Postgres אמיתי בזיכרון (PGlite). PayPal, Meta, ElevenLabs ו-Make מדומים.
- **דפדפן (45 בדיקות, `npm run e2e`):** הדפים האמיתיים ב-Chromium, מול שרת מקומי עם ה-API האמיתי. ה-SDK של PayPal והווידג'ט של ElevenLabs מדומים.
- **בדיקת הבדיקות:** שברתי בכוונה שלושה מנגנונים: אידמפוטנטיות התשלום, דרישת ההסכמה, ובדיקת הבעלות על הזמנה. בכל פעם בדיקה אחרת נכשלה. כלומר הבדיקות תופסות רגרסיה, ולא רק עוברות.
- **Make:** קריאה אמיתית לתרחיש החדש. שלוש ריצות עברו (status 1).

**לא נבדק בסביבה אמיתית:** Vercel Functions בפועל, Neon, PayPal sandbox, ה-webhook האמיתי של ElevenLabs, ו-Meta Test Events. כל אלה ממתינים למשתני הסביבה (ראו טבלת החסמים).

## באגים שנמצאו ותוקנו במהלך הבדיקה
1. אירועי מדידה שנוצרו רגע לפני מעבר ל-PayPal או לדף התודה אבדו. התיקון: אירועים קריטיים נשלחים מיד, ולפני ניווט יש flush.
2. "ממתין לנתוני שיחה" הופיע בכל הזמנה, גם בלי שיחה, כי כל הזמנה קיבלה מפתח קישור. התיקון: המפתח מוצמד רק כשהשיחה התחילה בפועל. בנוסף, אחרי שעה בלי נתונים מוצגת שגיאה ("לבדוק את ה-webhook").
3. בדשבורד חושבו שיעורים בין מספרים ממקורות שונים: מבקרים שהסכימו מול כל ההזמנות, וזה נתן שיעורים מעל 100%. התיקון: שיעור מוצג רק בין שלבים מאותו מקור.
4. במייל ה-paid של Make חסר שדה הסביבה.
